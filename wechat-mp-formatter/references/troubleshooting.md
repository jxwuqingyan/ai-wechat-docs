# 排错清单

## 症状 → 原因 → 解法

| 症状 | 原因 | 解法 |
| --- | --- | --- |
| 粘贴时弹「内容结构检测」提示 **pre 标签使用**、移动端可能水平溢出 | 代码块用了 `<pre>` 承载 | 用当前版本重新生成（默认已不使用 `pre`）；产物里出现 pre 会被 `check_html.py` 主动报出来 |
| 代码长行在手机上被折成两行 | 默认 `--code-mode block` 会对超长行折行（避免溢出） | 若更在意单行原样，改 `--code-mode scroll`，代价是超宽部分可能要横向滚动才能看全 |
| 粘贴时提示 **white-space:pre** 相关风险 | 用了 `--code-mode scroll` | 换回默认 `block`；这是为了避免溢出而做的取舍 |
| 粘贴后样式全没了 | 用了 class / `<style>` 标签 | 重新跑 `convert.py`，并用 `check_html.py` 验证 |
| **代码块挤成一行**（`EOFvm.swappiness = 1` 这种） | 分行依赖了 `<span style="display:block">`。微信重排时会洗掉 span 上的 `display`，行与行之间又没有任何真正的换行标签，于是无缝拼在一起 | 用当前版本重新生成：每行是一个 `<section>`，块级来自标签语义。`check_html.py` 会把这种写法直接报成错误 |
| 代码块里每一行都成了一个独立小块（行距过大） | 每行 `<section>` 里又补了 `<br>` | 去掉 `<br>`：块级本身已经换行，再补会叠出空行 |
| 代码缩进没了 | 空格被 HTML 折叠 | 脚本已把空格转 `&nbsp;`；若手动改过 HTML 要留意 |
| 代码块没有颜色 | 语言没写或语言不被支持 | 围栏处补语言名，如 ` ```go `；不支持的语言会降级纯文本但不乱版 |
| `<` `>` 变成了 `&lt;` 之类乱码 | 发生了二重转义 | 脚本是先分词后转义的；不要用其他工具二次处理生成的 HTML |
| **同一标题下的有序项全是 `1.`**（中间夹了说明段落或代码块的列表尤其明显） | 序号是 `<li>` 靠 `list-style` 画的；列表被正文/代码块打断后又被拆成多个 `<ol>`，每个都从 1 开始 | 用当前版本重新生成：序号已写成文本（`1.` / `•`），并会跨打断续号；`check_html.py` 把产物里的 `ol`/`ul`/`li` 直接报成错误。详见 `wechat-editor-rules.md` 第 5 节 |
| 有序列表里混进了项目符号项（圆点变成了数字） | 解析器只比对缩进、不比对标记类型，紧跟有序列表的无序列表会被吞进同一串编号 | 已修：标记类型（有序↔无序）变化即断开成两串列表。Markdown 与 Word 两条路径都要回归 |
| 换行后的第二行没有和首行正文对齐 | 列表项的悬挂缩进依赖 `padding-left` + `text-indent`，被洗掉后只是不缩进（不会错行） | 属于可接受的退化；若要调整缩进量改 `Renderer.LI_INDENT`，不要只改其中一处 |
| 表格没边框 | 微信不给表格默认样式 | 脚本已写 `border:1px solid`；不要额外用 `<style>` 定义 |
| 图片在预览里有、粘贴后裂图 | 本地路径或 base64 微信不收 | 在公众号后台上传图片后替换 src |
| 标题前的小竖线 / 圆点错位 | 用了 flex 布局 | 脚本用的是 `display:inline-block` + `vertical-align`，不要改成 flex |
| 行号被一起复制走 | 行号也是普通文本 | 需要干净复制就关掉 `--line-numbers` |
| 微信里空行被吃掉 | 段落用空 `<p>` 撑间距 | 脚本用 `min-height` + margin，避免依赖空段落 |
| 转换失败的原因只在右下角闪一下就没了 | 早期版本用 toast 显示错误 | 现在失败原因会写进左侧「待处理项」面板并自动展开（可停留、可复制），toast 只是提示去看一眼 |

## Word(.docx) 输入的处理约定

Word 里没有「代码块」这种东西，脚本用下面三条启发式规则识别：

1. **等宽字体**：run 的字体是 Consolas / Monaco / Menlo / Courier New / Source Code Pro /
   JetBrains Mono / Fira Code / Cascadia / SFMono 等（占当前段字符数 ≥ 80%）
2. **样式名**：段落样式名含 `Code` / `代码` 等关键字
3. 连续的这类段落会被合并为**一个**代码块，中间的空白段保留为空行

**给用户的建议**：写稿时把代码段设置成 Consolas（或上述任一等宽字体），这是最稳的标注方式。

**软换行必须还原成换行**：很多人在 Word 里写代码是「整段 + 软换行」（Shift+Enter，
底层是 `<w:br/>`）。早先 `_code_text()` 只取 `<w:t>`，整段代码会被压成**一行** ——
用户看到的正是「代码格式错乱、挤成一坨」。现在 `<w:br/>` 会还原成 `\n`，
并且在 `_assemble()` 里按行拆开后再参与缩进归一化。
改这段逻辑时务必用「整段 + 软换行」的 docx 回归（普通段落里的 `<w:br/>` 走的是
`_run_inline`，那条路会转成 `<br>`，不受影响）。

**只认 `.docx` / `.docm`**：其它格式必须明确报错，不能兜底当 Markdown 读。
`.doc` / `.rtf` / `.wps` / `.odt` / `.pages` 会被拦下并提示「请在 Word 里另存为 .docx」；
扩展名不认识又含 NUL 字节的二进制文件也会被拦下。早先的做法是静默按文本读，
结果是吐出一篇乱码文章 —— 这比报错更糟。

**语言怎么指定**：在代码段**上方另起一段**，只写一个语言名即可，例如 `python` 或 ` ```python `。
这段会被识别为语言标记并自动吃掉（不会出现在正文里）。不写就按纯文本渲染（不乱码，但无高亮）。

其他 Word 元素的映射：

| Word 元素 | 映射结果 |
| --- | --- |
| 标题样式 Heading 1~4 / 标题 N | h1 ~ h4 |
| 项目符号 / 编号 + numbering.xml | 每项一个 `<section>` + 文本序号/圆点（**不输出 ol/ul/li**），支持多级缩进；同一 `numId` 被正文打断后接着编号，换了 `numId` 则从 1 重新开始 |
| 表格 | table（首行自动作为表头） |
| 加粗 / 斜体 / 下划线 / 删除线 | strong / em / u / del |
| 字体颜色 / 高亮 | `<span style="color/background-color">` |
| 等宽字体的行内 run | 行内 `<code>` |
| 超链接 | `<a href>`（建议用 `--link-mode text`） |
| 图片 | 提取到 `xxx_images/` 目录，正文里嵌 base64 预览 |
| 图片（DrawingML / VML 两种写法） | `a:blip` 与 `v:imagedata` 都支持 |

**图片必须在 `<w:r>` 内部找**：Word 一定把 `<w:drawing>` 放在 run 里，
只在段落层级遍历的话，`_run_inline` 遇到纯图片的 run（没有 `w:t`）会直接 `continue` 跳过，
结果就是「报告说提取到 N 张图、正文里却一张都没有」——这个 bug 真出现过，
修法是 `_drawing_html(node, doc)` 在 run 子树里再找一遍。改这段逻辑时务必用带内嵌图的 docx 回归。

**无法可靠处理**：公式（OMML）、艺术字、SmartArt、文本框内容、批注、修订标记、复杂分栏。
遇到这些建议让用户改用 Markdown，或把该部分截图成图片再插入。

## Markdown 支持范围

支持：ATX 标题、段落与软换行、粗体 / 斜体 / 删除线、行内代码、围栏代码块（``` 与 ~~~）、
引用（含嵌套块内容）、有序 / 无序列表（含多级嵌套、列表内代码块）、表格（含对齐冒号）、
分隔线、图片、链接、自动链接、转义字符 `\`。

不支持（会当普通文本处理）：脚注、定义列表、LaTeX 公式、HTML 表格、内联复杂 HTML 布局、
GFM 告警块（会渲染成普通引用）。

## Web 工作台（server.py）相关

| 症状 | 原因 | 解法 |
| --- | --- | --- |
| 端口被占用 | 8765 已被别的进程占了 | 服务会自动往后递增端口，看终端里打印的实际地址即可 |
| 页面空白 / 按钮没反应 | 直接双击打开了 `assets/web/index.html`（file:// 协议，接口不可调） | 必须用 `python3 server.py` 启动，再访问 `http://127.0.0.1:8765/` |
| 「复制全文」失败 | 浏览器剪贴板 API 不可用 | 127.0.0.1 属于安全上下文，正常情况下可用；失败时脚本会自动回退到「选中区域 + execCommand」方案 |
| 下载的文件名乱码 | 浏览器不认 `filename*` | 现代浏览器都支持；若真遇到，改名即可 |
| 上传 Word 后想看原文 | Word 内容不在编辑器里显示 | 工作台只展示解析结果；要改内容请点「清空」后用 Markdown 编辑 |
| 草稿没恢复 | 内容超过 400KB 不会写 localStorage | 大文档请直接上传文件，不要依赖草稿 |
| 「合规自检」面板点了收起没反应 | `.check-panel` 上的 `display:flex` 盖过了浏览器默认的 `[hidden]` 规则（作者样式优先级更高） | 必须保留 `.check-panel[hidden]{display:none}`；任何用 `hidden` 属性控制显隐、又在 CSS 里写了 `display` 的元素都有这个坑 |
| 手机预览里 WiFi / 信号图标糊成一团 | 图标是用 CSS 渐变 / 多个 div 拼的，`radial-gradient` 画不出扇形弧带的锐利切口 | 状态栏三个图标已改为内联 SVG（见 SKILL.md「手机预览」一节）；**不要**再用渐变拼图标 |
| 手机预览只看到上面一小截 / 底部被切掉 | 用压缩机身尺寸（`height:min(896px,100%)`）而不是整体缩放，屏幕内容区不再等于 402px | 机身尺寸固定 `424 × 896`，可见性交给 `fitPhone()` 里的 `transform: scale()` |
| 手机预览里正文折行位置和真机不一样 | 缩放算法改成了压宽度，或改了 `.phone` 的宽度/内边距 | 屏幕内容区必须正好 402px（机身 424 − 左右各 11），正文可用宽度 362px（再减左右各 20 内边距） |
